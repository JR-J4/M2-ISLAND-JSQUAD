## Чому немає `enum Species`

Enum був зручний, але робив дві речі, які заважали:

1. **Подвійна особистість.** Вид існував двічі: як клас `Wolf` і як константа `Species.WOLF`.
   Дані виду й поведінка виду жили в різних місцях і мусили збігатися вручну.
2. **Закритий перелік.** Додати вид можна було тільки правкою самого enum, а зібрати другу
   екосистему (наприклад, острів без хижаків для перевірки) — ніяк.

Тепер `Species` — **звичайний незмінний обʼєкт-опис**, який створює `Ecosystem`:

```java
Species grass  = ecosystem.plant ("Трава",  "🌿",  1.0, 200,                  3200);
Species rabbit = ecosystem.animal("Кролик", "🐇",  2.0, 150, 2, 0.45, 4,      1600, Rabbit::new);
Species wolf   = ecosystem.animal("Вовк",   "🐺", 50.0,  30, 3, 8.00, 2,       600, Wolf::new);

rabbit.eats(grass, 100);
wolf.eats(rabbit, 60).eats(mouse, 80);       // порядок = що хапаємо першим
```

Розподіл обовʼязків став чесним: **`Species` відповідає за дані виду, клас-нащадок `Animal` —
за поведінку**. Дрібний, але показовий наслідок: один клас може обслуговувати кілька видів —
«сірий вовк» і «полярний вовк» з різними характеристиками, той самий `Wolf.class`.

Швидкість при цьому не втрачено: `Ecosystem` видає кожному виду `index()`, і клітинка тримає
мешканців у масиві за цим індексом — так само швидко, як `EnumMap`.

## Як шукається здобич

Було: на кожен прийом їжі створювався список усієї їжі в клітинці й **сортувався**. Миша серед
200 рослин щоразу отримувала список на 200 елементів і ~1500 порівнянь — щоб зʼїсти одну.

Стало: у виду вже лежить **готове меню** (`Prey[]`, порядок переваги задано при оголошенні), а
клітинка вміє за O(1) сказати `count(вид)` і видати випадкову особину. Жодних списків, жодного
сортування, жодного сміття:

```java
for (Prey prey : me.diet()) {                       // 1–3 записи, не 200 обʼєктів
    int nearby = cell.count(prey.species());        // O(1)
    for (int i = 0; i < nearby && attemptsLeft > 0 && satiety < fullMeal; i++) { ... }
}
```

Разом із цим прибрано ще три речі, які коштували найбільше:

| Було | Стало |
|---|---|
| `Comparator` створювався на кожен прийом їжі | порядок переваги порахований один раз при старті |
| видалення з клітинки — пошук по списку, O(n) | останній зі списку стає на звільнене місце, O(1) |
| щотакту список усіх тварин острова + перемішування | обхід клітинок, один буфер на весь такт |
| `Direction.values()` копіював масив на кожен крок | один спільний масив |

**Заміряно** (`javac`+`java`, 30 тактів, найкращий з 5 прогонів):

| Острів | Було | Стало |
|---|---|---|
| 100×20 (розмір з ТЗ) | 296 мкс на 1000 тварин | **143 мкс** |
| 20×40 (за замовчуванням) | 237 мкс на 1000 тварин | **129 мкс** |

Нормовано на тварину, бо нова екосистема тримає в 1,5 раза більше живності. Профіль (JFR)
показує, що тепер на їжу йде ~10% часу замість половини.

Одна ідея перевірки не пройшла: обходити списки клітинки напряму, без буфера-снапшота.
Виглядало швидше, заміряно — 5,31 проти 4,93 мс/такт, тобто гірше. Залишено простіший варіант,
у коді про це є коментар.

## Структура

```
config/    Settings                        параметри симуляції
organism/  Species, Prey, Ecosystem        дані видів і меню
           Organism -> Plant
                    -> Animal -> Herbivore -> Rabbit, Mouse
                              -> Predator  -> Wolf
island/    Island, Cell, Direction         світ
           Dice, Statistics                кубик і лічильники
           View, ConsoleView, Simulation   вивід і цикл тактів
```

* `Cell` — мешканці розкладені по видах у масив за `Species.index()`; `count`, `anyOf`
  і `remove` працюють за O(1).
* `Island` — сітка, один такт, володіє `Settings`, `Dice`, `Statistics`.
* `Dice` — уся випадковість. `new Dice(seed)` дає однаковий прогін (перевірено: два запуски
  з `seed(42)` збігаються байт у байт), `new Dice()` бере `ThreadLocalRandom`.
* `View` — інтерфейс. Потрібна JavaFX/Swing-графіка — напиши свою реалізацію, решту не чіпай.

Пакети `organism` та `island` посилаються один на одного: тварина живе в клітинці, клітинка
тримає тварин. Цей звʼязок природний для моделі; ціна — метод `Organism.placedAt` мусить бути
public, хоча його викликає лише `Cell`. Якщо хочеться суворої інкапсуляції — ці два пакети
варто зʼєднати в один `model`.

## Хто чим відрізняється (ООП по ділу)

`eat()`, `reproduce()`, `move()` живуть в `Animal` — вони однакові для всіх. Відрізняються
нащадки трьома **гачками**:

| Клас | Що перевизначає | Що це дає |
|---|---|---|
| `Predator` | `chooseDirection()` | голодний іде в сусідню клітинку, де найбільше здобичі |
| `Herbivore` | `chooseDirection()` | тікає туди, де найменше його ворогів (`species().hunters()`) |
| `Wolf` | `chanceToCatch(Prey)` | зграя полює краще: +5% за кожного сусіда-вовка |
| `Mouse` | `chooseDirection()` | сита миша сидить у нірці й нікуди не біжить |

Окремого `eat()` у травоїдного й хижака немає навмисне: різниця між ними — це рядок у меню,
а не окремий алгоритм. Саме тому травоїдна качка спокійно їстиме гусінь, коли її додадуть.

Огляд сусідів (`bestNeighbour()`) вмикається лише тоді, коли є заради чого: хижак — коли
голодний, травоїдне — коли хижак уже в його клітинці. Спершу він працював завжди й займав
половину часу симуляції.

## Як додати новий вид — 3 кроки

1. рядок в `Ecosystem.standard()`;
2. клас: `public class Fox extends Predator { public Fox(Species s, Island i) { super(s, i); } }`
3. меню: `fox.eats(rabbit, 70).eats(mouse, 90);`

Види оголошуємо знизу вгору харчовим ланцюгом — тоді меню посилається лише на вже створені
види, і кільце «А їсть Б, Б їсть А» неможливе за побудовою.

## Про рівновагу на острові

Двом травоїдним на одній траві не вижити разом: сильніший рано чи пізно виживає слабшого
(це справжнє екологічне правило, а не баг). Тому в кожного своя їжа — кролик пасеться на
траві, миша живе на зерні. Перевірено: 300 тактів, 4 різні зерна — усі три види живі,
популяції гойдаються (вовк 280–2900, кролик 5900–28000, миша 2600–25000).

Ще один запобіжник — `huntAttempts`: за такт тварина робить не більше 12 спроб схопити
здобич. Без нього вовк, щоб набити 8 кг, вирізав би за такт півтори сотні мишей, і миші
зникали б з острова назавжди.

## Багатопотоковість (наступний крок)

Місце підготовлене: увесь такт — це один виклик `island.tick()` у `Simulation.run()`.

* `Executors.newScheduledThreadPool(...)` + `scheduleAtFixedRate(island::tick, ...)`;
* усередині такту роздати клітинки звичайному пулу;
* зробити потокобезпечними списки в `Cell` і лічильники в `Statistics` (`AtomicInteger`).
  `Dice` до цього вже готовий — без зерна він бере `ThreadLocalRandom`.
